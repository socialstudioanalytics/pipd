§01 — Concept

The information environment is asymmetric. The tool corrects a small part of that.

Pali Answers does not try to "win arguments." It gives ordinary users — students, journalists, organisers, citizens — a fast, sourced, dignified rebuttal to claims they encounter every day.

Problem 01

Talking points outrun corrections.

The same dozen claims circulate everywhere — "Israel left Gaza in 2005", "Hamas = ISIS", "from the river to the sea is genocidal". Each takes seconds to deploy and hours to refute properly.

Problem 02

General-purpose AI hedges.

Mainstream chatbots tend to launder these claims as "complex" or "two-sided." They rarely point users to UN, ICJ, B'Tselem, HRW, Amnesty, or Adalah primary sources.

Problem 03

The good answers exist — scattered.

Rigorous responses live across reports, books, legal filings, and op-eds. Pali Answers consolidates them into one canonical answer corpus, query-matched and citation-backed.

§02 — Methodology

How a query becomes an answer.

A retrieval-augmented pipeline: the corpus does the truth-telling, the model only handles matching and tone. The LLM never invents claims; it only re-expresses the human-written answer that was retrieved.

Fig. 1 — System architecture
User query → semantic match → human-written answer → LLM rewrite → cited response
i

Normalise & gate.

Lowercase, strip punctuation, run a lightweight moderation classifier. Off-topic queries ("recipe for hummus") get a polite redirect; toxic queries ("how do I…") get refused. Everything else is forwarded.

regexclassifieri18n-aware
ii

Embed & retrieve.

The query is embedded with a multilingual embedding model and matched against pre-computed embeddings of every canonical question and every search-variation phrasing in the corpus. Top-k results are cosine-ranked.

text-embedding-3-smallpgvector / Pineconek=4
iii

Threshold & route.

If the top match exceeds the confidence threshold (τ ≥ 0.65), the system commits to that canonical question. If the score is borderline (0.45 – 0.65), it returns clarifying buttons ("Did you mean…"). Below 0.45, it falls back to a "we don't have an answer for that yet" template — never to free-form generation.

no-fallback-hallucinationdisambiguation UX
iv

Compose with constraints.

The matched canonical answer(s) — already written and reviewed by humans — are passed to a small LLM with a strict system prompt: "Re-express the supplied answer in the requested register. Do not introduce facts. Preserve every citation. If the supplied answer is insufficient, say so."

Claude Haiku 4.5 / GPT-4o-minitemp 0.3cite-or-abstain
v

Render & cite.

Each response ships with the canonical question ID, 1–3 selected answers (the corpus typically holds multiple, intentionally), and a footer of primary sources with working links. Optionally: a "read deeper" panel and a "share as image" export.

streameddeeplink-friendlyshare-card

§04 — Assumptions & non-goals

What the tool is not.

The honest version of any system spec is the list of things you have decided not to do. These are ours.

Assumption Implication
Closed-domain answers only The tool only answers questions it has a curated entry for. It will not improvise on the war in Yemen, Lebanese politics, or general Middle East history. Out-of-scope queries are explicitly declined with a "not in scope" message.
Human-written, not AI-generated Every canonical answer is human-written by domain editors and source-checked. The LLM is a stylistic re-expresser, never an author. This is the single biggest defence against hallucination.
Sources are non-negotiable An answer without sources doesn't ship. If a claim cannot be tied to a primary source (UN body, ICJ/ICC filing, recognised human-rights org, peer-reviewed work, recognised journalism), the claim is removed.
Multiple answers per question is a feature The corpus already provides 3–8 distinct answers per question — legal, ethical, historical, rhetorical, comparative. Users see 1–3 by default, can expand for more. This trains the user to think in registers, not slogans.
Tone is dignified, not combative The system prompt forbids sarcasm, mockery, name-calling, and personal attack. The corpus is firm about facts and refuses bothsidesism, but it does not insult interlocutors. This is a moral choice and a strategic one.
Living document, not frozen Geopolitical reality changes weekly. The corpus has a CMS layer and a versioned history; "answer last reviewed: YYYY-MM-DD" is shown to the user. Corrections are public.
No identification of individuals The tool will not generate content about private individuals based on user input. It will discuss public officials only in their official capacity, with sources.
Adversarial robustness is finite A determined bad-faith user can always extract awkward output from any LLM. The mitigation is structural: the LLM has nothing to "leak" because it has no facts of its own — only the retrieved answer.
§05 — Implementation

A small, boring stack — by design.

Boring is the point. The interesting work is in the corpus, not the infrastructure. Every layer below is replaceable in an afternoon.

Layer 1 — Content
Source of truth: a Git-backed Markdown corpus.

~70 question files. Each has YAML front-matter (id, category, keywords, search variations, last-reviewed) and 3–8 answer blocks. Editors PR via GitHub; CI rebuilds embeddings on merge.

md · yaml · github actions · review by 2 editors min
Layer 2 — Retrieval
Vector search over questions + variations.

Embeddings precomputed per question and per search-variation phrase (the project already includes 4–6 phrasings per question). Stored in pgvector for <100 questions; Pinecone/Weaviate if it grows.

text-embedding-3-small · pgvector · cosine · top-k=4
Layer 3 — Composition
Small LLM with a hard system prompt.

Claude Haiku 4.5 or GPT-4o-mini. Temperature 0.3. Prompt explicitly forbids any claim not in the retrieved context. Output is JSON with answer text + cited source IDs that must be a subset of the retrieved sources.

structured output · refusal mode · 800-token cap
Layer 4 — Surfaces
Web app · embeddable widget · public API · Telegram/WhatsApp bots.

Next.js front end on the web; a 30 KB JS widget that any organiser can drop into a website; a documented REST API for partners (UNRWA-aligned NGOs, journalist toolkits); messaging-app bots for region-appropriate distribution.

next.js · cloudflare · vercel · twilio
Layer 5 — Observability
Every unmatched query is gold.

Queries that fall below threshold are logged (anonymised) and become the editorial backlog. New canonical questions are added monthly. This is how the corpus grows from 70 → 200 → 500 over a year.

posthog · grafana · weekly editorial review
Layer 6 — Languages
Arabic, English, Spanish, French day one.

The corpus is authored in English & Arabic in parallel; ML-translated drafts in ES/FR are reviewed by community translators before publishing. Multilingual embeddings let users query in any of these and retrieve from any of these.

paraphrase-multilingual-mpnet · human review gate
§06 — Cost model

Four ways to build it, priced.

At 5,000–10,000 queries a month — realistic for a focused civic tool, not a viral chatbot — token cost is a rounding error. The real cost is the platform you choose. Below: the same architecture, four different build paths, infrastructure-only.

Per-month run cost

Cmonthly  =  platform fee + LLM tokens + embed + vector + hosting

Each query consumes roughly 1,400 input tokens (system prompt + retrieved canonical answer + user query) and 400 output tokens (composed reply). At 10K queries/month that is ~14M input + ~4M output tokens — a few dollars on most modern APIs. The interesting variable is what surrounds the model.

§07 — Risks & roadmap

Where it can go wrong, and where it goes next.

The risks worth watching are not technical. They are editorial, legal, and political.

Risk · Editorial drift

An answer becomes outdated and no one notices.

Mitigation: every entry has a last_reviewed field; entries older than 6 months surface in the editorial backlog automatically. Death tolls, ICJ proceedings, and policy changes get watched lists.

Risk · Legal pressure

Frivolous defamation / "lawfare" attempts.

Mitigation: every claim is tied to a primary source. Sources are quoted, not paraphrased into our voice. Legal review gates the apartheid / genocide / war-crimes entries before any publishing.

Risk · Platform deplatforming

Hosting, payments, or app-store removal.

Mitigation: corpus mirrored on IPFS + GitHub. The web is one surface among many; the API and the widget keep working from any host. No payment dependency in the consumer flow.

Roadmap · v0.2

Voice + Telegram bot.

The same retrieval pipeline behind a STT/TTS layer for accessibility, plus a Telegram/WhatsApp surface for regional distribution where web reach is constrained.

Roadmap · v0.3

Source provenance graph.

For each answer, render the network of sources cited and how they cite each other. Lets users see at a glance that a claim isn't propped up by a single op-ed but by overlapping UN, NGO, and academic work.

Roadmap · v1.0

Federated corpora.

Same engine, different corpora. The architecture generalises to any closed-domain Q&A with a curated, sourced answer set — climate denial, vaccine disinformation, historical revisionism.
