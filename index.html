01Purpose & scope

What the platform is for, and the boundary this architecture deliberately draws.

The platform supports academic study of influence and lobbying networks: who the actors are, how they are connected, and what they have verifiably done. Its central discipline is that every stored fact carries a source — title, date, URL — and that interpretation is produced by the platform from aggregated facts, not entered by hand. Three linkage types anchor it: structural (formal ties), activity (dated co-participation), and output (co-produced texts with named signatories).

Scope boundary applied in this design

Covers the descriptive and analytical layers only — directory, relationship graph, source-cited activity ledger, network and time-series analysis, search, and reporting. Built for understanding a network, not for acting against the people in it.

Excluded by design: per-actor exploitable-vulnerability scoring and the recommended response-options workflow. The analytical substance of "structural dependencies" is retained in purely descriptive form; ingestion is scoped to lawful, public, or ethically obtained material.

03Ingestion streams

Three feeds, one rule: a fact arrives with its source or it does not arrive.

Stream 1

Manual entry

Researchers complete the block-structured forms. Every entry in Blocks 3–7 is mirrored by a source-library reference. Dates and named actors mandatory — generic groups are rejected in favour of named individuals where documented.

Stream 2

Media monitoring

Tracked outlets are surfaced as candidate evidence, then reviewed, attributed, dated, and attached to the relevant entry. Nothing enters a record without an operator confirming the citation.

Stream 3

Registry & web capture

Official sources — transparency registers, court filings, parliamentary declarations, annual reports — captured with provenance preserved. Scope limited to lawful, public, or ethically obtained material.

08Access & governance

An access-controlled research environment with provenance discipline throughout.

Because records concern named, often identifiable people, the environment is access-controlled: authenticated accounts, role-based permissions, and an audit trail of who changed what. The governing rules are enforced by the data model itself — one record per actor; a source for every factual claim; a date on every event; named actors rather than generic groups; an update-date on every modification; provenance preserved on every captured item. A working prototype now exists that reflects these rules — see slide 07.

Interpretation lives only in the analysis layer and is reproducible from the underlying facts. Operators contribute evidence; the platform derives the structure. That separation is what keeps the system a research instrument rather than an editorial one.

Design summary

Analytical-research scope · 10-block data model (B8 omitted, B7/B9 reframed) · three sourced ingestion streams · network, time-series and search analysis · citation enforced end to end.

20AI evaluation

"Every fact has a source" is enforceable only if the platform measures whether Claude — and any swap-in model — actually grounds its outputs. The eval suite ships with the platform.

Fixtures

Gold sets

Hand-labelled extractions from representative source types — parliamentary declaration, court filing, op-ed, press release. Versioned; expanded by reviewers as edge cases surface.

Score

Citation grounding

Per-record metric: percentage of assertions whose evidence is retrievable in the source library and points back to a real span. Failing records are quarantined until a human commits.

Detector

Hallucination rate

Assertions present in the JSON output but absent from the source text. Tracked per model and per prompt version; spikes block deployment.

Quality

Precision · recall

Against the gold set, per field. Thresholds set per workload — extraction tolerates lower recall than analyst-RAG citation correctness.

Drift

Model upgrade gate

New Claude / Mistral / Llama versions run on the gold set before promotion. Regression on grounding or hallucination blocks the upgrade; manual review required.

Versioning

Prompts & A/B

Prompts under version control with hashes recorded against every record. A/B comparisons for substantive prompt changes; rollback is a one-line config change.

Evaluation results are themselves stored in the source library and surfaced in dashboards — the platform's quality is auditable from inside the platform.

22Roadmap & launch gating

Phased rollout with explicit gates. No tier promotes until its quality, security, and compliance criteria are demonstrably met.

Phase 1

Alpha · internal

2–4 internal researchers. Seed corpus of ~60 actors is already assembled (slide 28). Citation-grounding score > 0.85 on the gold set; basic SSO; daily backups. UI surface for this phase is covered by the prototype (slide 07). Goal: validate the data model holds up against real sources.

Phase 2

Beta · limited

5–10 invited internal researchers. Subject-rights workflow live; 99.9 % uptime over the prior 30 days; SLOs tracked. Claude Code has cleared a full security & architecture review pass.

Phase 3

Institutional · multi-team

Multi-team private deployment. Multi-region DR drill completed; on-call coverage; correction pathway operational. Still private — no public tier at any phase.

Cross-cutting

Accessibility

WCAG 2.2 AA target by GA. Keyboard navigation, screen-reader semantics, colour-contrast checks in CI, focus management on the network graph.

Cross-cutting

i18n

EN · FR · DE UI at launch, matching the source-doc languages. RTL support on roadmap if Arabic / Hebrew sources enter the corpus. Translation memory shared with the DeepL pipeline.

Cross-cutting

Partner API

Read-only API behind authenticated institutional keys post-GA — the platform is not for public use. Rate-limited; same RLS as the UI; results signed with provenance.
